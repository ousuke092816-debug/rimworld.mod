## 利用方法

二つ以上の直接拠点を連絡局に登録し、MOD設定で実物輸送を有効にする。「輸送を手配する」の同行者一覧で入植者とプレイヤーの動物を選ぶ。動物だけでは出発できず、通常のキャラバンを所有できる入植者が一人以上必要。死亡・ダウン・徴兵・精神崩壊中の個体、他の便に予約された個体は選択対象にしない。野生動物や他国の動物は対象外。

装備・既存の所持品・追加の積荷を含む重量と、選択した一行の運搬能力を表示する。重量超過や選択内容の変化があると予約ボタンを無効にする。サービスを直接呼ぶ経路でも予約前に同じ条件を検査する。出発時にも再検査するため、予約後に所持品が増えた場合は元のマップで便を保留する。余分な荷物を降ろしてから同じ便の出発を再試行できる。

荷物を運べる動物はゲーム本体の能力を使う。同行できる動物すべてが荷物持ちになるわけではない。運搬重量はキャラバン全体の計算で、各スタックを個々の所持重量に収めるための追加分割は行わない。

## 保存と照合

人間の `people / personCount` を維持し、動物専用の `animals / animalCount` を追加した。動物はCoreの `animal` 種別、物理権限、元Pawn参照、負荷ID、元のThingDefを恒久IDへ結び付ける。Colonyが元個体を複製・再生成する処理はない。個体の状態の保存主体はゲーム本体。

輸送依頼は従来の人物列に加えて動物列と件数を保存する。動物が含まれる依頼だけ、不可変の依頼ハッシュへ `native-animals-v1`、恒久ID、元負荷ID、ThingDefを加える。動物のない旧便のハッシュは変更しない。追加テーブルのない0.4.0〜0.4.3の保存は空の動物列として読み込む。

同じ個体を複数の便に予約できない。取消では元個体をマップから動かさず、予約のみ解除する。出発・移動・到着・不足照合は人間と動物の全個体を確認する。元の動物が欠けた便は保留し、配送品の不足を受け入れる操作で動物の欠落を解消しない。元の動物が同じキャラバンに戻れば照合し直せる。救出や代替個体への変更はまだない。

出発済み・到着済みのチェックポイント復旧は元キャラバンと個体の所在を観測し、既存のCore確定証を再利用する。読み込みで動物、貨物、キャラバンを作り直さない。動物の結合変更、動物の依頼列の削除、動物テーブルの欠落は復旧前の検査で拒否する。

## 運搬重量の根拠

参照したのはこのPCのRimWorld 1.6.4871 rev591の実DLL。`Caravan.MassUsage` と同じ `CollectionsMassCalculator.MassUsage`、`IgnorePawnsInventoryMode.DontIgnore`、二つのbool引数falseを使い、選択品の `StatDefOf.Mass × 数量` を加える。運搬能力は `Caravan.MassCapacity` と同じ `CollectionsMassCalculator.Capacity`。装備・既存の所持品を自己流の固定値へ置き換えない。

実積荷はスタックごとに元スタックから分割し、荷物を運べる同行者のうち空き重量が最大の個体へ渡す。所持品への追加時は結合を無効にして元貨物IDを維持する。ゲーム本体のキャラバンと同様に合計の運搬能力で判定し、作成したキャラバンの実重量と能力も確認する。ゲーム本体の `GiveThing` は結合や失敗時の破棄を行う経路があるため、ID保持が必要な輸送では直接利用しない。

## 検証

最終検証の結果と画像は `Evidence/P04Animals` に収録する。ゲーム本体・ゲームDLL・試験セーブは配布しない。元のゲーム設定・セーブは更新せず、隔離した実行環境を使う。

- AnimalSave：旧0.4.2の完了保存を開く。重量超過・動物のみの便・二重予約を拒否し、元資産とCore件数に副作用がないことを検査。取消・予約の反復と動物専用結合も確認。
- AnimalReserved：別プロセスで予約保存を開く。元の名前・種族・性別・年齢・所属・傷を照合。予約後の所持品増加で出発を保留し、荷下ろし後に元個体を出発させる。表示重量・能力と実キャラバンの値の一致、荷物持ち動物への積荷割当を確認。
- AnimalLoad / AnimalFinal：輸送中・到着後の別プロセス再開。同行動物の欠落を荷物の損失として処理しない。元の動物を戻し、動物の所持品内の鋼鉄75→74の不足を一度だけ確定。標準経路で到着・保存・再開して同じ個体と貨物IDを保持。
- AnimalDepartureCheckpoint / AnimalArrivalCheckpoint：確定済みの証のローカル参照が未確定の状態を構成し、移動を再実行せず既存証を再利用、Core件数を維持。
- PhysicalFaultLoadのAnimalBinding / AnimalManifest / AnimalMissing：保存を改変してメニューへの読み込み拒否と原本SHA256一致を確認。
- AnimalRenderEnglish / AnimalRenderJapanese：実ゲームの描画で動物の選択、重量と予約を確認。日本語の公式パック既存注入エラーは基本36／四DLC28件の全内容と比較する。実マウス操作の検証とは区別。

隣接タイルへの経路更新を加速する試験で、世界タイルを直接書き換えない。通常の食料・休息・襲撃や動物の長期飼育を含む総合運営は未確認。個体年齢のみ、再開直後の標準更新を0〜3 tick許容する。独立レビュー完了、P04全体の完成、最新Steam配信revの照合済みとは扱わない。
