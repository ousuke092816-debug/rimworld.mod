# P03 六国家の簡略世界 — 実装と確認

2026-10-07。Core / World 0.3.0。実ゲームの試験版はRimWorld 1.6.4871 rev591。

## 完成した試作の範囲

六国家の抽象世界、初期文化圏、L1〜L4の都市、首都、管理変更と履歴、抽象収入、遷都を保存・再開できる。国家の初期予算は各100、都市構成と収入率も同じで、六文化を初期数値で不公平にしない。これは将来の兵站・戦争調整の土台であり、戦闘力の調整を完了した意味ではない。

| 文化キー | 国家 | 初期首都 |
|---|---|---|
| starmound | 碑原評議会 | 第一碑庭 |
| irontree | 根海共同体 | 万根の庭 |
| forge | 炉路氏族連盟 | 千炉環 |
| whitecrown | 白冠諸侯盟約 | 白冠の座 |
| tidering | 潮衡水務連邦 | 分水の都 |
| skymark | 遠標観測同盟 | 灯群台 |

各国に村・町・都市・首都候補の四段階を一つずつ、合計24都市。都市のレベルと首都の役割は別欄にした。占領されたL4都市が自動的に征服国の首都になることはない。

国家や都市はCore台帳のpolity/cityレコードで、RimWorldのFactionやSettlementオブジェクトへまだ接続していない。世界マップの訪問、地区生成、戦争AI、プレイヤーの占領操作、税アイテム、文化アセット、旧派閥・敵の置換は未実装。建築・武器・種族パックの独立性を保ったまま後続工程へ接続する。

## 初期配置

実際の惑星表面から、海・通行不能・拠点を建てられないタイルを除いて候補を取得する。地形の中心座標は球面上で扱う。シードの安定したハッシュで最初の中心を選び、既存中心から離れた候補を順に選んで六中心を作る。最寄り中心へ文化圏を割り当て、その圏内で四都市を分散配置する。

同じシード、地形、計画版なら同じ配置となる。生成計画のハッシュは配置・文化・初期構成を含み、実行中の管理変更、収入、Coreの採番は含まない。ロード時に実地形と保存済地形のハッシュも照合する。将来、地形を変更する他MODへの許容・移行契約を追加するまでは、途中で候補地形が変わった保存の利用を拒否する。

座標を小数5桁へ固定し、ハッシュでは正負ゼロを同値にした。XML往復で負のゼロが正のゼロとなり、同じ地形を不整合と判断した実試験の問題を修正した。

## Coreの保存版3と起動順

Coreヘッダーはschema 3、Coreモジュール保存版3、共通モジュールprotocol 2。Worldのデータ版・モジュール保存版は1。

- 1→3：同じ世界GUIDのまま空台帳を作り、1→2と2→3の移行履歴を一度ずつ保存する。
- 2→3：既存台帳・GUID・連番を保持し、通常モードで2→3の履歴を一度記録する。
- 新しい世界：設定に応じてvanilla / six-nationsを決める。
- 既存世界への後付け：Coreの保存欄がない場合も、読み込んだ世界へ新規生成用設定を適用しない。
- 読み込んだモード：保存値を維持し、新規生成用の設定変更で切り替えない。

既存バニラへの後付けで新規用設定が誤って効く可能性は、独立担当のレビューで指摘された。保存欄のロード有無と、世界そのものがロード由来かを分離して修正し、追加済セーブのロード経路を実ゲームで確認した。

Core検査・復旧とWorld生成・検査が終わるまで通常の書き込みAPIを閉じる。生成中は登録されたWorld担当の書き込みのみ許可する。ゲームスレッド、現世界、互換性、保存中・再入禁止の検査を共通で適用する。

## パック欠落時の保存形式

World固有のWorldComponentをゲームのScribeへ保存する方式は廃止した。`WorldStateComponent`は名前を維持した通常の実行時サービスであり、WorldComponentを継承しない。

CoreWorldComponentが`inheritanceWorldPayload`文字列をScribe_Valuesで保存する。WorldはDTOをXmlSerializerでその文字列へ変換し、ロード時にDTD禁止・外部解決なしのXmlReaderで復元する。Core以外の保存クラス名を外側のゲームセーブへ書かない。

これによりWorldを外してもゲームが欠落クラスを復元しようとする例外は起きず、Coreが必要パックの欠落を検出してメニューへ戻せる。モードがsix-nationsなら、台帳が空でもWorldと保存版情報が必須。通常モードにWorldのpayloadがある保存も拒否する。開発専用のWorldSmokeの保存コンポーネントは配布MODに含まれず、パック欠落fixtureではその開発用記録だけ除いている。

## 再生成と占領

生成キーに対応するCore操作を先に探し、同じ要求でPrepared / Committedを再実行する。生成計画の操作ID・結果IDと台帳を照合し、既存IDを付け直さない。全国家と都市の検査を終えてReadyにする。

占領はまず指定時刻までの旧管理国の収入を精算し、Coreの管理変更操作とWorld側のチェックポイントを保持する。Core確定後に首都の役割を更新する。Core Applyingの保存や、Coreが確定済みでWorldが未反映の保存も同じ操作を再開する。

同じ原因・同じ要求の占領を再実行しても履歴を増やさない。同じ原因で別の征服国を指定すると拒否する。都市のCultureKeyとOwnerIdを維持し、ControllerIdのみ変更する。首都を失った国は残る最上位の管理都市へ遷都し、同順位は生成キー順で決める。全都市を失った場合は首都なし・臨時状態とするが、この全都市喪失ケースの実ゲーム試験はまだ追加していない。

Coreは都市の初期生成操作、管理変更journal、管理履歴の件数・順序・操作ID・旧新管理国・時刻・最終管理国を照合する。WorldもチェックポイントとCoreの履歴を照合する。履歴を削除した保存を経済精算へ流さない。

## 抽象収入

現在の収入率はL1〜L4で1・4・9・16。量は整数の「率×経過tick」を保持し、表示だけ60000tickで一日単位に換算する。毎日の自動精算と占領前の精算は同じ処理を使う。実物資・銀・税の支払いではない。

収入記録のキーは都市・開始時刻・終了時刻・管理国で固定する。区間に抜け・重なりを認めず、履歴から導かれる管理国・額と一致させる。同じ終了時刻の再精算は加算しない。未確定の占領がある間は精算を止める。現在の区間記録は伸び続けるため、長期性能と履歴集約をP13までに検証する。

## 実ゲームで通した試験

以下は隠したゲームプロセスによる動作確認。元のゲーム設定・セーブを変更せず、隔離した保存先と実行環境で行った。

| 試験 | 結果・範囲 |
|---|---|
| PrototypeSave（基本／四DLC） | 六国家・24都市、L1〜L4、首都、建築可能な別々の候補地、予算100、計画再計算一致。首都占領をApplyingで保存 |
| PrototypeLoad（基本／四DLC） | 同じGUID・30個の国家／都市ID・計画を保持。占領一回だけ確定、元国はL3へ臨時遷都、征服国の首都は保持 |
| PrototypeCompletedLoad（基本／四DLC） | 確定保存を別プロセスで再開。同じ占領の再実行で重複せず、異なる要求を拒否 |
| 収入試験（基本／四DLC） | 二日分で元国44・征服国76・他国各60、総計360相当。同じ時刻の精算で増加しない |
| PlanResume（基本／四DLC） | 最後の都市生成を未確定へ戻したチェックポイントから再開。国家／都市30IDと計画を維持、都市の二重生成なし |
| VanillaAttach（基本／四DLC） | Core保存欄のない既存世界へ追加してロード。新規用設定が有効でも通常モード・空台帳のまま |
| 破損World保存6種（基本） | payload欠落、モジュール版情報欠落、配置改変、管理履歴欠落、収入重複、収入管理国不一致を拒否。メニュー復帰、原本SHA256一致 |
| RequiredWorldLoad（四DLC、World無効） | 必須World欠落を検出してメニュー復帰。欠落クラス例外なし、原本SHA256一致 |
| 旧P02の実セーブを移行 | 2→3でGUID、連番、Pawn参照、物資100、管理履歴を保持 |
| Core単独の再試験 | schema 3の新規保存→再開→確定保存再開。100個の予約・分割・到着、元Pawn参照維持 |

PlanResumeは再開可能な保存チェックポイントを試験用に構成しており、ゲームを強制終了して保存ファイルを途中切断した試験ではない。VanillaAttachは保存データを持たない世界の追加後ロード経路を直接試験し、MOD追加時の確認ダイアログのクリックを検証したものではない。

証拠の抽出ログは`Docs/Evidence/P03`。CS1684警告と、隔離起動時のSteamAPI初期化失敗は残る。Steamの機能を試験したものではない。GUIの見た目・クリック操作、通常プレイを続けた長期試験、複数設定・大量シード、Workshop版packageIdの差、最新Steam配信revの照合は未確認。
