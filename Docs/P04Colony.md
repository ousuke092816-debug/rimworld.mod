# P04 連絡局 — 0.4.0の実装記録

2026-10-07。RimWorld 1.6.4871 rev591の実DLLでビルドし、隔離した実ゲームで確認。P04全体は制作途中。

この文書は0.4.0の履歴。0.4.1で追加した実物予約・恒久人物ID・標準経路・保存復旧はP04TransportIntegration.mdを参照。

## 現在の完成範囲

Core＋Colonyで、プレイヤーの実マップを直接拠点として登録し、マップを持たない委任拠点の記録を作れる。Worldへの依存はない。拠点名・都市ID・マップID・直接／委任の区別を保存する。登録済みマップの再登録で都市IDを付け直さず、マップを改名しても二重登録しない。連絡局の一覧から、各直接拠点の住民数とマップ上の鋼鉄数を参照できる。

抽象在庫の登録、輸送予約、出発、到着、取消、到着時刻での自動処理を実装した。抽象在庫の登録APIは開発試験からのみ使用し、プレイヤー向けに物資を作るボタンは設けていない。通常プレイの実物資は抽象台帳へ自動変換しない。

人物・実物資の輸送は、ゲーム標準のキャラバンを使う技術試作まで実装・試験した。連絡局の輸送予約・恒久個体登録・世界移動・委任拠点への実物引き渡しはまだ接続していない。この試作アダプターは開発用の起動引数がないと動作せず、通常プレイの操作画面へ公開していない。

## 共通保存版4

Core 0.4.0はschema 4、共通module protocol 2。Colonyのモジュール保存版は1。Worldのデータ版は1のまま。

Coreが複数モジュールの保存文字列と件数を保持する。保存に現れるクラスはCoreのModulePayloadだけで、ColonyのDTOクラスをゲームのScribeへ書き出さない。Colonyを外した場合はCoreが必要な所有モジュールと保存アダプターの欠落を検出し、例外で欠落クラスを生成しようとせずメニューへ戻す。

保存文字列の所有者・版・件数とモジュール定義を照合する。復元は世界・マップのロードが完了してから行い、Core・World・Colonyの検査が終わるまで通常の書き込みを開放しない。モジュール更新中に不整合が起きた場合も通常処理を止める。

- 1→4：同じGUID、空台帳、三段階の移行履歴。
- 2→4：同じGUID・連番・台帳、通常モード、2→3と3→4の履歴。
- 3→4：同じGUID・連番・台帳・World保存文字列・世界モードを保持し、3→4の履歴。
- 4を再読込：移行履歴や既存IDを増やさない。

未使用のColonyは空の保存文字列を作らない。Colonyの台帳記録があるのに保存文字列がない場合は拒否する。以前の0.4.0作業途中セーブも試験に使用したが、公開済み対応版は旧0.1.0・0.2.0・0.3.0の確定ZIPを基準にする。

## 抽象輸送の契約

原因ID、出発地・目的地、元ロット、数量、到着予定時刻と開始revisionから、長さ付きの正規化文字列とハッシュを作る。生成したCore shipmentにこの要求の識別子を保持する。同じ原因・同じ要求の再実行は同じ輸送便を返し、数量・目的地・予定時刻が変わった再利用は拒否する。

Planning → Reserved → Departing → InTransit → Arriving → Arrived。未出発のReservedはCancelling → Cancelledで解放できる。出発済みの貨物を未出発予約と同じ処理で取り消さない。

予約は元在庫の内数。出発時に元ロットを減らして子ロットを輸送便に置き、到着時に同じ子ロットの保管場所だけを変更する。到着したロットの一部を別便で再輸送しても、元の便は歴史上の到着記録として保持する。ロットの親子関係と全量を照合する。

途中状態の保存は、同じCore操作を探して再開する。復旧前に保存チェックポイントの要求を元のshipment・予約journalへ照合する。改変された要求でいったん物資を動かしてから拒否する順序を避けた。予約数量・状態、到着先、元／貨物のID、保管場所、数量保存、孤立レコードを検査する。

## 実物輸送の技術試作

PhysicalCaravanAdapterは、同じPawnとThingを標準のCaravanへ移し、ゲーム本体を物理保存の正本にする。複製したPawnを名前で代用しない。選択数量だけSplitOffし、キャラバンの所持品へ入れる際はスタックの結合を無効にして積荷IDを維持する。到着時は元キャラバンの同じ住民と所持品を第二マップへ入れ、貨物を勝手に抽象在庫へ足さない。

出発前に現世界・ゲームスレッド・プレイヤーマップ・人物の所在と状態・積荷の所在と数量・重複選択を確認する。不正な数量は何も移す前に拒否する。出発や入場を同じ個体で繰り返しても、新しい個体やキャラバンを作れない。移動中の失敗では元の物体を戻す処理を用意したが、失敗後の復元経路を網羅的に試験したわけではない。

この段階は即時の出発と目的地への入場を技術確認する経路であり、予約して待機中のAIによる物資消費、自然な旅程と食料、襲撃、死亡・積荷損失、既存キャラバンとの競合、委任拠点にマップを開かず住民を保管する処理は未実装または未確認。

試験では到着条件を確認した後、開発コードがキャラバンのタイルを目的地へ移した。自然な世界移動と所要時間を実証した試験とは区別する。技能、傷、遺伝子、思想、装備、持ち物のIDを保存前後で照合した。四DLCの試験には機能する内生遺伝子Robustと外来遺伝子DarkVisionを追加する。基本ゲームには遺伝子・思想の必須参照を作らない。

ColonyResumeは中断可能な状態を試験用に構成したもので、保存ファイルを途中切断した試験ではない。複数設定・大量シード・長期運営・画面の目視とクリック操作は未確認。Coreの古いコンパイラーでSpan関連CS1684警告は残る。

初期試験で英語の翻訳XMLの閉じタグ誤りが見つかった。修正して全MOD／試験MODのXML構文を照合し、翻訳読込エラーを試験失敗として扱うよう実行手順を強化した。実物試験ではゲームの鋼鉄スタック上限75に合わせて有効なスタックを使用するよう修正した。

証拠はDocs/Evidence/P04。最終確認の結果と限界を制作記録に残す。主担当の確認を独立レビュー合格として扱わない。

## 次に接続するもの

1. 連絡局の保存済み要求と、実物アダプターの出発・入場を一つの再実行可能な操作へ接続する。
2. 実物予約中の在庫変化、元個体の恒久登録、自然な世界移動、貨物の引渡しを検証する。
3. 委任拠点で実住民・動物・装備を維持し、生産と維持費を実マップと二重に処理しない。
4. 輸送指示・取消・不足・到着・保留を通常の操作画面へ接続する。
5. Solを基本に独立した差分レビューと回帰試験を行い、P04の完了条件を満たす。

P04の実物輸送と委任が統合完了するまで、P05の市場地区やP06の都市失陥を完成扱いにしない。Astraはユーザーの新しい希望に従い自動的に割り当てず、既存指示書のSol中心方針を使う。
