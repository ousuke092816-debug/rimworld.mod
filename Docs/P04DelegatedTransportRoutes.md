# P04 委任地点への通常輸送と別記録による帰路 — 0.4.9

2026-10-08、Asia/Tokyo。直接操作する拠点から位置付き委任地点への往路を、既存の実物輸送コマンドへ接続する。停止した元キャラバンで到着を確定すると、往路の予約を解放して元住民・元動物を委任保管へ移せる。全員を同じキャラバンへ戻した後、往路の履歴を維持したまま別の帰路記録を作り、元の直接拠点へ帰還する。

**状態：最終116試験成功。** 通常委任便の8段階、帰路の復旧3種、帰宅証未発行fixtureの生成、記録改変5種、旧保存と従来機能を基本ゲーム58・四DLC58で実行し、配布DLLと実行環境のSHA256を照合した。過去の0.4.8で成功した82ログは、その版の結果として維持し、0.4.9の成功件数へ流用しない。試験を通過しても、P04全体の完成を意味しない。

## 保存形式と互換性

Core保存schema 6、ColonyとWorldの保存schema 1、module protocol 2を維持する。新たなCore保存schema移行は追加しない。ColonyStateへreturnCountとreturns、PhysicalTransportRecordへdestinationTile=-1を追加する。旧保存で省略された項目は空の帰路表・件数0・destinationTile=-1として扱う。

通常の直接拠点間輸送はdestinationTile=-1を維持し、既存PhysicalManifestのハッシュ入力を変えない。地表の委任地点へ向かう新規輸送だけがdestinationTile>=0を持ち、delegated-destination-v1とタイル番号をハッシュ入力へ追加する。委任都市の恒久IDと記録された地表タイルが一致することを検査し、別地点への差し替えを拒否する。既存の位置なし委任拠点を実物輸送先として使うことはできない。

帰路はDelegatedReturnRecordを一便につき一つ持つ。往路causeを参照し、帰路自身のcause、shipment、出発証明、帰還証明、段階、問題を保存する。帰路manifestは元の往路shipment・出発／到着証明、元Caravan負荷ID、元直接都市・mapId、委任都市・地表タイル、元人物・動物の恒久binding、貨物負荷ID、受容済み往路損失証明へ結び付く。同じcauseの別往路への再利用や、他のColonyコマンドとのcause衝突を拒否する。

## 往路の操作契約

| 操作 | 動作 |
| --- | --- |
| ReservePhysicalTransport | 元直接拠点、位置付き委任都市、元隊列、元貨物を照合し、既存の実物輸送予約を作る |
| BeginPhysicalDeparture / DispatchPhysical | 通常の出発検査と現物アダプターを使い、元隊列と選択貨物を一つのゲーム側キャラバンへ移す |
| StartPhysicalRoute | タイルの直接書き換えをせず、ゲーム側StartPathと通常tickで委任地点へ進む |
| BeginPhysicalArrival | 同じ地表タイルで停止した元キャラバン、元隊列、貨物、所有関係を照合してArrivingにする |
| DeliverPhysical | マップへ入場せず、同じ停止中のキャラバンで到着証明を確定し、往路をArrivedにする |

委任到着では現物を抽象在庫へ変換せず、委任地用マップを生成しない。元Pawnを代用品に置き換えず、貨物はゲーム側の通常のstack分割で運ぶ。直接拠点間の標準入場も既存の動作を維持する。

委任輸送ではキャラバンの全人数とmanifestの元人物・動物の総数が一致すること、各元Pawnが元キャラバンのThingOwnerとWorldPawnsへ整合して登録され、他キャラバンへ重複登録されないことを照合する。負傷・ダウンなどの保管可否と、到着した現物隊列の観測は別に判定する。到着を観測できても、その個体が直ちに凍結保管できるとは限らない。

Arrived後は往路単独の活動中予約が解放され、既存StoreDelegatedPawnを使える。保管できる元住民・元動物だけをCoreへ移し、利用可能な別の人間の護衛を元キャラバンに残す。Arrived前の隊列を重ねて保管したり、帰路予約中の個体を保管したりすることはできない。

## 帰路の操作契約

| 操作 | 動作 |
| --- | --- |
| BeginDelegatedReturn(cause, outwardCause) | 完了した往路、同じ委任地点で停止中の元キャラバン、戻った元全隊列・貨物、予約競合を検査して別shipmentと出発証明を作る |
| StartDelegatedReturnRoute | 同じ元キャラバンを元直接拠点へ通常経路で戻す。同じ帰還経路が進行中なら再開指示で進行を巻き戻さない |
| BeginDelegatedReturnArrival | 元直接拠点のタイルで停止した全隊列・貨物を照合し、標準入場前のArrivingを保存する |
| DeliverDelegatedReturn | ゲーム側の標準入場で元Pawnを元マップへ戻し、帰還証明を作ってReturnedにする |
| RecheckDelegatedReturn | NeedsAttentionの元現物を再照合する。隊列が揃った元キャラバンならInTransit、元マップへ入場済みなら帰還を明示的に確定する |

帰路を始めるには、往路manifestの元住民・元動物を護衛も含めて全員、同じ元キャラバンへ戻す必要がある。保管中、未完了のCore移管、別の活動中輸送・帰路との予約競合、別キャラバン、増員した隊列を拒否する。拒否条件は帰路shipmentを割り当てる前に検査する。

元貨物負荷IDと数量契約も維持する。旅程用補給物は既存の消費許容契約に従う。その他の貨物は往路の受容済み数量を照合し、帰路中に変わった場合はNeedsAttentionとする。帰路独自の損失受容や補充は今回追加しない。隊列・貨物が戻らなければ止め、Pawn・貨物・キャラバンを再生成して修復しない。

帰路が活動中の間は元隊列を輸送予約として扱い、他便への二重使用や凍結保管を防ぐ。Returned後はその予約を解放する。往路のPhysicalStage.Arrived、元出発証明、元到着証明を帰路段階に書き換えない。元キャラバンが標準入場で消滅した後も完了履歴を維持し、完了した帰路の再実行は現在のキャラバンや個体位置を再要求せず、移動や証明を重ねない。

## 途中保存と読み込み

往路の復元は既存実物輸送の方式に従う。Arrivingを読み込み、同じ委任地点の停止中キャラバン・元隊列・貨物が一致した場合、到着leaseとcreate operationを一組、新規に確定する（Core資産件数+2）。これは現物移動やマップ生成ではなく、保存済み到着意図の証明確定である。往路復元を「Core割当なし」とは扱わない。

帰路の読み込みは、既にCommittedになったCore operationから欠けた証明参照を復元し、現物の所在地を観測する。新しいshipment・lease・operationを作らず、キャラバン移動、マップ入場、Pawn移動を行わない。Arrivingで元キャラバンが元マップ前に残っている場合はInTransitへ戻して明示的な入場操作を待つ。元Pawnがすでに元マップにいるが帰還証明が未作成ならNeedsAttentionにし、RecheckDelegatedReturnで明示的に確定する。

証明がすでに存在する場合は参照を復元してReturnedを維持する。帰還済み履歴の検査は、元キャラバンが現在存在することや元Pawnが現在も帰還時の位置にいることを条件にしない。元個体・貨物が欠けた活動中帰路を、完了した過去履歴として扱うことはしない。

## 有効化と残作業

新しい委任地点の登録、新規委任便の予約、新規凍結保管には開発フラグinh-delegated-custodyが必要である。通常の凍結保管設定だけではこれらを有効化しない。保存済みの出庫・移管再開は既存資産を回復する経路を維持する。

帰路コマンドはCoreへの書込許可とPhysicalGateを必要とし、inh-delegated-custodyは要求しない。実物輸送設定を無効にした場合に帰路コマンドまで無条件に許可する契約ではない。今回の輸送・保管試験は隔離した開発用環境で行う。

通常の委任操作画面、委任地点WorldObject、食料の委任消費・生産・維持費、委任生活の更新、一括のマップ撤去／委任切替、失った元キャラバンの代替回復、帰路独自の損失受容は未実装である。現物輸送接続ができたことを、委任経済や多数拠点運営の完成として扱わない。

## 最終試験

新しい通常便の8段階は基本ゲームとRoyalty・Ideology・Biotech・Odysseyの四DLC構成を別設定・保存先で実行する8段階ずつ、計16試験。Anomalyは対象外である。各段階を別ゲームプロセスで再開し、今回のDLLと結果ログを照合する。全16段階が今回の実行で成功した。
