# P04 食料の目安と通常の旅程 — 0.4.5

2026-10-07、Asia/Tokyo。Core / World / Colony 0.4.5。Core保存版4、World / Colony保存版1、module protocol 2を維持。P04全体は制作途中。

## 通常画面へ追加したもの

輸送指示画面に「出発地での食料の目安」を追加した。選択した住民・動物、積荷数量、元個体の所持品を、ゲーム本体の `DaysWorthOfFoodCalculator.ApproxDaysWorthOfFood` へ渡す。出発地タイルとプレイヤー所属を使用する。食料や台帳を変更する処理ではない。

計算不能は同行者の選択案内、ゲーム本体の無制限値は「当面の制限なし」と表示する。実DLLの `InfiniteDaysWorthOfFood` は600。住民の現在の満腹度や動物の放牧条件も本体計算へ影響するため、食料を追加していなくても短い日数を表示する場合がある。選択する個体と数量を変えると目安を再計算する。

全経路の日数、途中の気候・地形、食料の腐敗時期を合わせた完走予測ではない。目安が短いことだけを理由に短距離便を拒否しない。荷重と物資予約の既存検査は維持する。

配送用の食料もゲーム本体の食事候補になる。「旅用食料」の指定は消費順序の指定ではなく、輸送記録で減量を許容する用途区分である。配送品の食料を減らせば、従来の不足照合へ進む。画面にもこの注意を表示する。

## 通常の時間進行による実ゲーム試験

試験はRimWorld 1.6.4871 rev591、基本ゲームとRoyalty・Ideology・Biotech・Odysseyの四DLCで実行した。Anomalyなし。隔離環境を使用し、元のゲーム設定・セーブは変更していない。

`TickManager.DoSingleTick()` を一度ずつ呼び、毎回TicksGameが1増えることを検査した。処理を一画面更新あたり300 tickずつ進めるが、マップ・世界・住民・キャラバン等の通常更新を通す。タイルの直接変更、時間ジャンプ、経路処理だけの更新はしない。

元住民一人、元Muffalo一頭、配送鋼鉄10、旅用の簡単な食事10と干し草80を予約・出発する。試験開始時だけ空腹・休息を低くして、実際の食事と休息を観測しやすくした。出発後に本体の経路を停止して待機し、半日で保存してプロセスを終了する。別プロセスで続け、一日以上の通常進行後に同じ便の経路を再開して到着させる。

以下を両構成で確認した。

- 食料を追加すると目安が増え、計算だけではCore件数が増えない。
- 人の食事・休息、動物の空腹解消、標準の夜間休息状態を観測する。
- 食事が実際に消費され、配送鋼鉄は10のまま、不足確定証は追加されない。
- 半日保存の再開で元個体・元便・元物資のID、食料残量、需要の状態を維持する。
- 標準経路と自動入場で元住民・動物・鋼鉄を目的地へ届ける。
- 到着保存を別プロセスで再開しても食料を補充せず、到着確定を重複させない。

別の便では旅用の食事を一個にし、本体の食事によって元スタックがゼロになるまで通常更新した。減量を直接設定する試験とは異なり、元住民が実際に摂取する。途中保存の再開でも食事を再生成せず、元依頼の数量1と旅用区分を保持し、不足証とCore件数を増やさない。

## 証拠と限界

`Evidence/P04Journey` にログ抜粋、元ログのSHA256・時刻、試験DLLの照合結果、日本語・英語画面を収録する。基本の日本語・英語と四DLCの日本語を実ゲーム描画で目視した。日本語は公式パックだけの既存注入エラーと全内容を照合した。実マウス操作は未検証。

これは一日の待機と隣接拠点への通常移動の試験である。長距離遠征、遭遇襲撃、季節をまたぐ腐敗、気候別の放牧、疲労した部隊の長期運用、長期性能の合格とは扱わない。動物の空腹解消には本体の放牧・食事条件を使用し、専用の給餌処理は追加しない。委任拠点の需要処理は `P04DelegatedCustody.md` の後続工程。
