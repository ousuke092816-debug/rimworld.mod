# P02 実装と保存契約

2026-10-07。Core 0.2.0 / schema 2 / module protocol 2。RimWorld 1.6.4871 rev591の実DLLでビルド・実ゲーム試験済み。

## 実装した範囲

全種別で共有する64bit恒久連番、世界GUID、モジュール保存版、旧版1から2への移行、所有・管理・文化・所属・保管・更新責任を分離した台帳を追加した。読み取りはコピーされたsnapshot、書き込みはゲームスレッドの検証済み現世界だけに限定する。

人物は抽象記録または元PawnへのScribe参照を持つ。Physicalの数量はゲーム本体が正本で、抽象数量へ足さない。参照未解決・一体の二重登録を拒否する。物理個体の移動、死亡、統合、保管先切替はP04のアダプターへ残した。今回の実物試験は元Pawnへの参照維持である。

抽象物資の作成、予約、解放、出発時の分割、到着時の保管変更、抽象個体の移動、都市管理欄と履歴の変更を操作ID付きで実装した。予約は在庫の内数であり、出発時に元ロットを減らして同量の子ロットを輸送便へ置く。到着後も子ロットのIDを変えない。

## 再実行と復旧

操作IDに対して全要求を長さ付きで正規化し、全文とSHA256を比較する。同じ要求は既存結果、変更された要求は拒否。異なる操作IDでも同一モジュール・操作種別・原因IDの重複を拒否する。

Preparedは未適用、Applyingも今回の抽象操作では未適用の状態を保存する。確定は全体コピーへ適用・検査してから一度だけ置き換える。保存中・確定中の再入を許可しない。読込時は必要な前提ID集合、revision、対象と予約の保存内容fingerprintを確認し、一致するApplyingだけPreparedへ戻す。違いがあればNeedsReconciliationに保留してロックを維持する。物資を推測で補充しない。

税・生産の時刻精算や、未出発予約を含む占領計画はWorld/Colony側の次工程で接続する。管理欄変更の原語だけで占領全体が完成した扱いにはしない。

## 保存読込

世界読込のFinalizeInitはマップとPawnの参照解決より早いため、全LongEvent完了後に検査・復旧する。それまでは台帳を公開しない。

schema 1は当時のGUIDを維持して空台帳・次番号1へ移行する。都市や物資を作らず、移行履歴を記録する。schema 2でヘッダー、台帳、必須数量・状態、提供元、版、ID、必要前提が欠けた場合は利用を止めてメニューへ戻る。版99等の未対応版も同様に拒否する。既存バニラへのCore追加はヘッダーと台帳の両方がない場合に限り新規状態とする。

モジュールの保存版は厳密一致。保存データを持つモジュールの解除は拒否する。現在未使用の追加パックは導入でき、使っていない任意パックの解除も許容する。モジュールごとの移行実装は今後追加する。

## 実ゲームで確認したこと

- 基本ゲーム・Royalty/Ideology/Biotech/Odysseyの両構成で新世界保存、別プロセス再開、確定保存、さらに別プロセス再開。
- 100個から30個を予約→Applying保存→Prepared復旧→出発70/30→到着70/30。二重確定・再読込・再実行でも総量100。
- 解放、過剰予約拒否、予約済ロットの移動拒否、要求不一致拒否、同一原因の別操作拒否、中止、ロック、別スレッド書込拒否。
- 抽象人物のIDと所属維持、元Pawn一体への参照維持、都市の管理国変更・文化と所有保持・履歴一件維持、連番後退なし。
- 実P01セーブの1→2移行と、移行後の別プロセス再開。移行を重複記録しない。
- 前状態改変はNeedsReconciliationとして保留。確定できず、貨物を生成しない。
- 未来版と12破損fixtureを拒否し、メニュー復帰を確認。試験元ファイルのSHA256は一致。

破損fixtureはヘッダー欠落、台帳欠落、連番後退、数量欠落、状態欠落、操作前提欠落、別世界GUID、所有先欠落、表欠落、ID重複、所有モジュール欠落、モジュール未来版。全種類を基本ゲーム、未来版・復旧を四DLCでも確認した。任意の改ざんを修理する機能やセーブ全体のチェックサムではない。
