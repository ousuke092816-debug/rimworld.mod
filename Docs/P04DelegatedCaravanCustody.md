# P04 委任地点と元キャラバン間の凍結保管 — 0.4.8

2026-10-08、Asia/Tokyo。委任地点へ通常移動で到着した元キャラバンから、元住民・元動物をCoreへ凍結保管し、同じ地点の同じ元キャラバンへ戻す開発用接続を追加する。**最終82試験が成功**。基本ゲーム41・四DLC41の最終ログと配布DLLのSHA256を照合し、既存保管画面3枚を目視した。以前の結果を今回の成功件数へ流用せず、今回の実行ログをEvidence/P04DelegatedCaravanへ保存した。P04全体は未完了。

## 保存形式と移行

Core保存schemaを6へ更新する。Colony保存schema 1とmodule protocol 2は維持する。Coreの移管記録へcaravanIdとtileを加え、キャラバン端点ではmapId=-1、cell=IntVec3.Invalidとする。端点は元キャラバンの負荷IDと地表のPlanetTile(tile, 0)の組であり、別のキャラバンや別の惑星層へ差し替えない。

マップ端点はcaravanId=null、tile=-1を使う。従来のマップ移管のHash入力を一切変えず、schema 5の確定証を同じハッシュで照合する。キャラバン端点だけにpawn-custody/caravan-v1の区別とキャラバンID・地表タイルをハッシュ入力へ加える。端点の形が曖昧な記録、元個体のbindingと異なる記録、確定証と異なる記録は拒否する。

schema 1〜5からの移行は各保存版の元ヘッダーと、その版に存在する元資産を検査したうえでschema 6へ進む。schema 1は台帳を含まない旧形式として検査し、schema 2・3は元ヘッダーによる台帳検査、schema 4は元モジュール印を使ったpayload所有者と台帳の検査を行う。schema 5ではさらに、元ヘッダーのままCorePawnCustodyの移管・在籍・元個体所有を検査してからproducerとmodule stampを更新する。古い印を現在の印へ先に置き換えて、不正な所有関係を隠す移行は行わない。

ColonyのBaseRecordへtile=-1を初期値として加える。保存schema 1の追加項目であり、旧保存の位置なし委任拠点もtile=-1として引き続き有効である。ただし位置なし拠点を現物保管の端点として使うことはできない。直接拠点のtileは-1を維持する。

位置を持つ委任地点はRegisterDelegatedSiteで登録する。同じkey・名前・タイルの再要求は同じ都市を返す。地点の識別キーにはタイルも含む。既存マップ、キャラバン以外のWorldObject、既存の位置付き拠点と重なるタイルや、同じ地点識別子での名前変更は拒否する。別の空きタイルは別の地点として登録できる。地点登録はColonyの拠点記録とCore都市の登録であり、委任地点用WorldObjectやマップを生成しない。

## 元個体の所有と操作契約

試験対象は、通常のゲーム側キャラバンが所有する元Pawnである。新しいPawnやキャラバンを代用品として作らず、名前、恒久ID、負荷ID、元Pawn参照と、装備・衣服・所持品の元子ホルダーを保つ。現物所持品を抽象在庫へ変換したり、両方へ二重計上したりしない。

入庫前・出庫後は、Pawnが非出現状態で元キャラバンのThingOwnerに属し、そのキャラバン一覧だけに一度存在し、WorldPawnsにも登録されていることを照合する。保管中はCoreのThingOwnerだけが元Pawnを持ち、マップ、キャラバン、WorldPawnsへ重複登録しない。入庫ではキャラバンから元Pawnを外してWorldPawns登録を解除し、出庫では元キャラバンへ戻してWorldPawnsへ明示的に登録する。

| 操作 | 契約 |
| --- | --- |
| StoreDelegatedPawn(cause, city, caravan, pawn) | 位置付き委任地点で停止中の元キャラバンから、未予約の元住民・元動物をCoreへ移す。別の利用可能な人間の入植者が護衛として残る必要がある |
| ReleaseDelegatedPawn(cause, city, entity, caravan) | 保存した在籍、入庫証明、地点、元キャラバンIDを照合し、同じ停止中のキャラバンへ元個体を戻す |
| ResumeDelegatedCustody(transferId) | 既存の意図をApplyNative、Commitの順で再開する。完了済みの意図は再実行しても追加の現物移動や証明を作らない |

新規の地点登録と入庫は、Coreの準備完了と開発フラグinh-delegated-custodyが必要である。通常の拠点内凍結保管設定custodyEnabledを有効にしても、この委任接続は有効にならない。出庫と保存済み意図の再開は、開発フラグを新規入庫の許可として要求せず、既存資産の回復経路を残す。通常プレイ向けの委任画面はまだ提供しない。

最後の利用可能な人間の護衛は保管できない。死亡、ダウン、徴兵、精神状態、乳児、他の物を運搬中、他providerのbinding、活動中の実物輸送や別の保管意図との予約競合を拒否する。既存の実物輸送に予約された個体を委任保管へ重ねないが、通常の実物輸送manifest全体と委任地点を結ぶ出発・到着フローは未実装である。

causeはactor内で同じ要求の再試行にだけ使う。個体、都市、方向、元キャラバン、タイルの変更は拒否する。マップ保管のcauseをキャラバン保管へ再利用することも、その逆も拒否し、拒否前に人物登録や追加証明を割り当てない。完了した履歴は、出庫して元キャラバンが帰還後に消滅しても保持する。

## 未確定意図、移動中の再開、凍結時間

Prepared、Applying、Committedの段階と、Core確定証、在籍表、元個体の実際の所有先を照合する。入庫のPreparedでは元キャラバン、ApplyingではCoreが元個体を持つ。出庫のPreparedではCore、Applyingでは元キャラバンが元個体を持ち、在籍の削除はCommitで確定する。同じ意図の再開は、既に適用された現物を照合して確定し、複製や補充で修復しない。

未確定意図の準備後に元キャラバンが移動を始めた状態も、元個体と所有関係が整合していれば保存・読み込みできる。保存時の安全な所有の検査と、現物移管を実行できる条件を分ける。実行時には元キャラバンが保存した地表タイルで停止していることを厳密に要求し、同じタイル上でも移動中なら拒否する。拒否は元個体や既存証明を変えず、停止後に同じ意図を再開する。

戻り先は保管時の同じ元キャラバンに限る。元キャラバンを失った場合も保管済み住民はCoreに残るが、代わりのキャラバンへの回復・付け替えは未実装である。別タイルにいる元キャラバンにもそのまま出庫できない。

保管中は元Pawnの通常更新を行わず、生物年齢、需要、技能経験値、傷、遺伝子、思想、現物所持品を凍結する。ただし暦年齢は世界の経過時計から算出されるため、世界時間とともに進む。暦年齢まで停止する契約ではない。キャラバンに残った護衛は通常の需要更新を続ける。食料消費、生産、維持費、治療、委任生活を代行する更新は未実装である。マップを撤去・削除する操作も追加しない。
