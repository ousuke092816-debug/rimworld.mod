## 実装範囲

連絡局へ登録した二つの実プレイヤーマップの間で、元の住民とマップ上の積荷を指定して実物輸送を予約できる。予約・取消・出発・標準経路の開始・到着・再実行をColonyServiceのAPIへ接続した。通常の輸送指示画面は未公開。開発引数 `inh-physical-probe` でのみ予約と実物の移動を許可する。

連絡局の一覧には、実物輸送の人数・個数・予約／出発／輸送中／到着／取消／要確認を表示するコードを追加した。問題の詳細は保存記録とログに残し、画面には現物の確認が必要であることを表示する。画面の目視・クリック検証はまだ行っていない。

ゲーム本体のPawn、Thing、Caravanを物理保存の正本にする。物理数量を抽象在庫へ足さない。実物予約は抽象Core reservationと異なる命令記録であり、物資の現物を予約直後に減らさない。AIによる消費を止める独占予約はまだない。出発直前に実際の所在・数量・住民の状態を再確認し、不足なら便を保留して移動しない。

## 識別子と要求の固定

- 住民はCoreのPhysical personとして元PawnのScribe参照に結び付ける。同じ住民を別便へ予約しても、人物IDを作り直さない。
- 人物の共同体・所属と、現在のマップ／キャラバンを分ける。今回の人物レコードは識別と所属を保持し、custodyは空。実際の所在は標準ゲームの保管場所を参照する。Coreの抽象moveで実人物を動かさない。
- 原因、出発／目的拠点、順序付きの人物IDと元Pawn ID、元スタックID、定義名、数量から要求ハッシュを作り、Core shipmentの作成journalへ固定する。同じ原因の別要求を拒否する。
- 出発時にはアダプターが実際に移したThingを直接返す。定義名と数量が同じ別スタックを推測して積荷とみなさない。積荷の結合を避け、分割後の元Thing IDを保存する。
- 出発・到着・取消の確定記録はCore leaseに作成する。出発・到着記録には便、キャラバンIDと実積荷IDを固定する。保存文字列の書き換えで別の貨物へ差し替えることを拒否する。

一人を複数の未完了便へ予約できない。同じ実スタックに対する未出発便の予約数量を合計し、別の住民による過剰予約も拒否する。予約内容の事前検査に失敗した場合、人物・便・キャラバンを作らない。

## 保存と復旧

Core保存版4、module protocol 2、World／Colony保存データ版1を維持。Colonyのschema 1へ人数・実物便の件数と追加テーブルを加えた。0.4.0以前の抽象便だけのColony payloadは、追加テーブルが空のものとして読み込む。新しい物理記録を古いColonyコードで利用する前方互換は保証しない。

Reserved → Departing → InTransit → Arriving → Arrived。未出発ならCancelledにできる。途中の現物が変わった場合はNeedsAttentionへ保留する。出発済み便を未出発予約の取消で解放しない。

読み込み時はまずCoreの要求・確定記録とpayloadを照合し、その後に現物の所在を観察する。読み込みだけを理由に住民を動かしたり、キャラバンを新規生成したりしない。

- 出発意図だけで現物が出発地にある：予約状態へ戻し、明示的な出発で再確認する。
- 元の便・人物・積荷が既にキャラバンにある：同じ出発記録を利用して輸送中へ確定する。
- 到着意図だけで現物がキャラバン内にある：輸送中へ戻す。読み込み時に入場を強制しない。
- 元の人物・積荷が既に目的マップにある：同じ到着記録を利用して到着済みへ確定する。
- 曖昧な所在、死亡・貨物の数量変化など：便を保留する。失われた個体や物資を生成して補わない。

出発・入場はゲームスレッドで同期実行する。Coreの保存中に移動しない。中断可能な意図と確定記録を別に保持するが、アダプター途中のあらゆる障害からの復元を網羅したわけではない。NeedsAttentionからの一般的な手動照合・再建画面は後続作業。

自動入場は開発用の `inh-physical-auto` と `inh-physical-probe` が両方あるときだけ有効。通常の実物試験は自動入場を止め、到着直前の保存を個別に確認する。自動入場の試験は別のPhysicalAutoLoadで行う。

## 実ゲーム試験の手順

RimWorld 1.6.4871 rev591。基本ゲーム＋Core＋Colony、Royalty・Ideology・Biotech・Odyssey＋Core＋Colonyを使用し、Anomalyは無効。旧抽象保存の回帰では四DLC＋World＋Colonyも使用する。結果と元ログのSHA256はEvidence/P04Integrationへ記録する。

| 試験 | 検査 |
|---|---|
| PhysicalSave | 75個の実鋼鉄を予約30・取消10・再予約。恒久人物IDの再利用、要求変更・人物二重予約・別人物によるスタック過剰予約の拒否。予約と出発意図の保存後に45／30へ分割 |
| PhysicalReservedLoad / PhysicalDepartureIntent | 予約／出発意図のロードで自動移動なし。鋼鉄を20へ減らす試験では出発を保留し、75へ戻して明示的に再出発。同じ便・元個体を維持 |
| PhysicalLoad | ルートと目的タイルの再開、早すぎる入場拒否。標準path followerで隣接拠点へ移動。元住民と貨物の入場、到着確定、反復処理 |
| PhysicalArrivalIntent / PhysicalFinalLoad | 到着意図・確定済み保存の別プロセス再開。個体・貨物・在庫総量と到着記録を維持 |
| PhysicalDepartedCheckpoint / PhysicalDeliveredCheckpoint | 保存payloadの参照だけが未確定の試験用チェックポイント。既存のCore出発／到着記録を再利用し、レジストリ件数を増やさない |
| PhysicalAutoLoad | 到着意図をロードし、開発用の自動入場と確定処理で一度だけ到着 |
| PhysicalFaultLoad | 数量・目的地・人物結合・テーブル欠落・出発記録欠落・貨物ID・偽の到着状態を拒否。メニュー復帰と原本SHA256一致 |
| ColonyFinalLoad | 0.4.0の旧抽象循環輸送を再開し、A75／B10／C15、総量100を維持 |

経路試験は隣接タイルを使い、標準path followerの更新を加速して行う。タイルの直接書き換えやNotify_Teleportedは使用しない。通常の長時間シミュレーション、食料消費、休息・病気・襲撃、世界全体の進行や自然な所要時間をまとめて実証した試験ではない。

人物検査はID・名前・性別・派閥・技能と経験・傷・遺伝子・思想・装備を比較する。予約中の実マップPawnではロード後に標準の保留されていた年齢更新が入る例があり、試験では生物年齢の差を0〜3 tickに限定して許容する。他の状態をこの許容で除外しない。四DLCでは内生Robust・外来DarkVisionを実際に持たせて照合する。

## 次の工程

1. 通常の輸送指示・住民／積荷選択・取消・不足・入場・要確認の操作画面を作る。
2. 本来のゲーム進行で食料・休息・移動速度・襲撃・死亡・貨物損失を確認し、保留便の照合と退避を作る。
3. 委任拠点への元Pawn・動物・持ち物の保管と、生産・維持費を接続する。
4. Sol中心で独立レビューと長期回帰を行い、P04の完了条件を満たす。

試験セーブは隔離したwork内だけで扱い、元のゲーム設定・ユーザーのセーブ・ゲーム本体を変更しない。ゲームDLLとセーブは配布ZIPに含めない。
